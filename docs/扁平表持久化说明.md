# TODO：runtime 通道改回「只存修整 ini，读入再展平」

> 状态：**暂缓**（非性能紧急项；先稳住模块进程被杀后的配置存活）  
> 记录日期：2026-11-08

## 目标

持久层（含跨进程 runtime 配置 / 目标侧镜像）只保存修整后的 ini（及必要元数据，如零声母策略）；  
`27×27` 扁平表仅在内存中、每次读入配置时推导，再交给 `nativeConfigure`。

## 现状（偏离点）

| 层 | 行为 | 是否符合目标 |
|---|---|---|
| `SchemeStore` | 只存 `ini`，读入时再解析/展开 | 是 |
| `config.txt` / 目标侧 `cached-config.txt` | 「应用设置」写入已展开 `flat` | **否** |

## 为何暂缓

- flat 体量小，读写仅在应用设置 / 冷启动，不在按键热路径；体感无差。
- 注入侧现在只解析 `key=py…`，改回要把 `SchemeParser` 拉进读配置路径。
- 当前优先修复：模块进程被杀导致注入失效（Provider 稳定连接连带杀客户端等）。

## 将来要做

1. `ModuleConfig` 序列化改为 ini + 元数据；去掉（或降级）`---table---` flat 段。
2. `HookEntry` / `loadForHook` 读入后调用与设置页同一套展开逻辑，再 `nativeConfigure`。
3. 给镜像文件加版本头；迁移或丢弃旧版含 flat 的 `cached-config.txt`。
4. 更新 `模块实现机理.md` 与设置页文案中「下发扁平表」相关描述。
5. （可选）LSPatch 路径下确认「目标本地快照」仍以 ini 为源、内存展平。

## 相关代码

- `SchemeStore` / `SchemeParser`
- `SettingsUiState` 应用设置 → `cfg.table = pr.scheme.flat`
- `ModuleConfig.publish` / `HookEntry.applyConfig` / `NativeBridge.nativeConfigure`
